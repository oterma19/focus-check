# Focus Check 1.0

Личное приложение, которое помогает **начинать** дела, **доводить их до конца** и **не винить себя**.
Работает прямо из папки на компьютере: без сервера, без интернета, без установки.

---

## 1. Как запустить

1. Все файлы лежат в одной папке (структура ниже — **папки `js` и `supabase` не переименовывать**).
2. Двойной клик по `focus-check.html` → откроется в браузере.
3. Лучше всего работает в **Chrome** или **Edge** (Firefox и Safari тоже подходят).

**Удобнее — по ярлыку:** дважды щёлкните `Создать ярлык.bat` — на рабочем столе и в «Пуске» появится
значок **Focus Check**, который открывает приложение отдельным окном. Телефон: см. файл
**«Инструкция — ярлыки Focus Check.docx»** (там же всё пошагово и для компьютера).

При первом запуске появится короткое знакомство (3 шага). Посмотреть его снова: *Настройки → Показать знакомство ещё раз*.
Чтобы быстро увидеть приложение «в жизни»: *Настройки → Заполнить примером*.

> **Где хранятся данные.** В памяти браузера (localStorage) на этом компьютере.
> Другой браузер = другие данные. Очистка истории браузера «со всеми данными сайтов» сотрёт записи.
> Поэтому иногда нажимайте *Настройки → Скачать резервную копию* (файл `.json`).

## 2. Структура файлов

```
ежедневник/
├── focus-check.html        ← открывать этот файл
├── index.html              ← короткий адрес сайта → ведёт на focus-check.html
├── styles.css              ← весь дизайн: цвета, отступы, телефон
├── manifest.webmanifest    ← название и значок для установки на телефон
├── sw.js                   ← работа без интернета на телефоне (только по https)
├── Создать ярлык.bat       ← двойной щелчок = ярлык на рабочем столе и в «Пуске»
├── README.md               ← этот файл
├── icons/                  ← значки приложения (PNG для телефона, ICO для Windows)
├── windows/
│   └── create-shortcut.ps1 ← скрипт, который запускает «Создать ярлык.bat»
├── js/
│   ├── config.js           ← настройки + места для SUPABASE_URL и SUPABASE_ANON_KEY
│   ├── utils.js            ← даты, id, защита текста
│   ├── content.js          ← ВСЕ тексты и подсказки (меняйте тон здесь)
│   ├── data.js             ← СЛОЙ ДАННЫХ: LocalAdapter (сейчас) + SupabaseAdapter (потом)
│   ├── auth.js             ← вход: сейчас «локальный пользователь», потом Google
│   ├── store.js            ← состояние в памяти + сохранение через адаптер
│   ├── models.js           ← правила: задачи, привычки, часы, фокус, статистика
│   ├── ui.js               ← иконки, окна, всплывающие сообщения
│   ├── screens/
│   │   ├── today.js        ← «Сегодня» + карточка задачи
│   │   ├── elephant.js     ← 🐘 «Съесть слона»: большие дела и кусочки
│   │   ├── focus.js        ← «Фокус» (таймер)
│   │   ├── routine.js      ← «Рутина» (привычки + по часам)
│   │   ├── progress.js     ← «Прогресс»
│   │   └── settings.js     ← «Настройки», резервная копия, пример данных
│   ├── flows/
│   │   ├── rescue.js       ← кнопка «Мне трудно» и три сценария поддержки
│   │   └── onboarding.js   ← знакомство при первом запуске
│   ├── pwa.js              ← включает установку на телефон (только по http/https)
│   └── app.js              ← запуск, переключение экранов, таймер (подключается последним)
└── supabase/
    └── schema.sql          ← таблицы и правила доступа для облачной версии
```

**Какие старые файлы заменить:** всё. Старые `app.js` и `styles.css` из корня больше не используются
(новый `styles.css` их заменяет, логика переехала в папку `js/`). Старую версию можно сохранить в
отдельную папку `old-v1/` на память. Данных в старой версии не было — она ничего не сохраняла.

### Почему много маленьких файлов, а не один `app.js`
Каждый файл отвечает за одну вещь. Хотите поменять экран «Фокус» — открываете только `screens/focus.js`.
Хотите поменять фразы — только `content.js`. Хотите облако — только `config.js` и `data.js`.

### Почему не `import/export` (ES-модули)
Браузеры запрещают модули при открытии файла двойным кликом (адрес `file:///…`).
Поэтому файлы подключаются обычными `<script>` по порядку, а общие объекты (`Tasks`, `Store`, `UI`…)
видны друг другу. Порядок подключения в `focus-check.html` важен.

## 3. Как устроено (для понимания и будущих правок)

```
  Экран (screens/*.js)                 — рисует HTML по данным
        │  кнопка data-action="toggleTask"
        ▼
  Actions.toggleTask()                  — что сделать по нажатию
        ▼
  Tasks.toggle(id)   (models.js)        — правило: задача стала «готово»
        ▼
  Store.save('tasks', task)  (store.js) — обновить память и перерисовать экран
        ▼
  Data.adapter.upsert(...)   (data.js)  — сохранить: сейчас localStorage, потом Supabase
```

- **Кнопки** связаны с действиями через атрибут `data-action="имя"` → вызывается `Actions.имя`.
  Поля ввода — через `data-change`, формы — через `data-submit`.
- **Экран перерисовывается целиком** после любого изменения. Для личного приложения это быстро и
  гораздо проще, чем точечно менять куски страницы.
- **Id записей — UUID**, поля названы как колонки базы (`created_at`, `task_id`).
  Благодаря этому переход на Supabase — это замена адаптера, а не переписывание приложения.

### 🐘 «Съесть слона по кусочку» — вложенные задачи
- Большое дело («слон») разбивается на кусочки: кнопка **🐘** рядом с полем добавления,
  или в карточке задачи **«Разбить на кусочки»**. Кусочки пишутся по одному на строку.
- Каждый кусочек — обычная задача: у неё свой день, время, фокус-таймер, отметка.
  В план дня попадают **кусочки**, а сам слон живёт в блоке **«Большие дела»** с полосой прогресса.
- Сделан кусочек → приложение предлагает взять следующий на сегодня. Съеден последний → слон закрывается сам.
- Вложенность — **один уровень** (у кусочка нет своих кусочков). Это сознательно: глубокие деревья задач
  превращаются в планирование вместо дела. Если кусочек слишком большой — разбейте его: новые кусочки лягут рядом.
- В базе это поле `parent_id` у задачи (см. `supabase/schema.sql`).

### 🔔 Напоминания о делах со временем (js/reminders.js)
- Если у задачи есть время (например, `15:30 позвонить в банк`), приложение напомнит **за N минут**
  (настраивается: в момент / за 5 / 10 / 15 / 30 мин) — системным уведомлением и мягким сообщением со звуком.
- **Ограничение веб-приложений:** напоминание приходит, пока приложение **открыто** (окно можно свернуть).
  Закрытая веб-страница сама себя «разбудить» не может.
- Чтобы напомнило при закрытом приложении — в карточке задачи кнопки **«Google Календарь»** и
  **«Файл для календаря (.ics)»**: тогда напоминает календарь телефона или компьютера.
- Настоящие push-напоминания при закрытом приложении — версия 2.0 (нужен сервер: Supabase + web push).

### Быстрые приёмы
- `15:30 позвонить в банк` — задача со временем.
- `завтра купить хлеб` — задача на завтра.
- Клавиша **N** — сразу к полю добавления задачи (на компьютере).
- Адрес `focus-check.html#focus` открывает сразу экран фокуса — можно сохранить в закладки.

## 4. Supabase: где и как подключать (этап 2)

### Что понадобится
- Аккаунт на supabase.com (бесплатного тарифа достаточно для личного приложения).
- Проект в Google Cloud Console для входа через Google.
- **Адрес http(s)** для приложения. Вход через Google **не работает при открытии файла двойным кликом**:
  после входа Google должен вернуть вас на настоящий адрес. Варианты:
  - для разработки: `python -m http.server 5500` в папке приложения → `http://localhost:5500/focus-check.html`;
  - для телефона: бесплатный статический хостинг (GitHub Pages, Netlify, Cloudflare Pages).

### Шаги
1. **Создать проект** в Supabase.
2. **Создать таблицы:** SQL Editor → вставить `supabase/schema.sql` → Run.
   Проверка: `select tablename, rowsecurity from pg_tables where schemaname='public';` — везде `true`.
3. **Ключи:** Project Settings → API → скопировать *Project URL* и публичный ключ
   (*anon* или новый *publishable*, `sb_publishable_…`) в `js/config.js`:
   ```js
   DATA_MODE: 'supabase',
   SUPABASE_URL: 'https://ВАШ-ПРОЕКТ.supabase.co',
   SUPABASE_ANON_KEY: 'ВАШ-ПУБЛИЧНЫЙ-КЛЮЧ',
   ```
   ⚠️ Ключ `service_role` / `secret` **никогда** не вставлять в код страницы.
4. **Библиотека:** в `focus-check.html` раскомментировать строку
   `<script src="https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2"></script>`.
5. **Google-вход:**
   - Google Cloud Console → APIs & Services → Credentials → *Create OAuth client ID* → *Web application*.
     В *Authorized redirect URIs* добавить `https://ВАШ-ПРОЕКТ.supabase.co/auth/v1/callback`.
   - Supabase → Authentication → Providers → Google → включить, вставить Client ID и Client Secret.
   - Supabase → Authentication → URL Configuration → добавить в *Redirect URLs* адреса приложения
     (`http://localhost:5500/focus-check.html` и адрес хостинга).
   *(Названия пунктов меню у Supabase и Google иногда меняются — ориентируйтесь на смысл.)*
6. Открыть приложение по http-адресу → *Настройки → Войти через Google*.
7. **Перенести локальные данные:** в старом (file://) варианте скачать резервную копию → в новом
   (после входа) *Восстановить из копии*. Это нужно потому, что `file://` и `http://localhost` —
   для браузера разные «сайты» с разными хранилищами. В `data.js` также готова функция
   `Data.migrateLocalToCloud()` для автоматического переноса.

### Где что лежит для облака
| Что | Где |
|---|---|
| `SUPABASE_URL`, `SUPABASE_ANON_KEY`, переключатель режима | `js/config.js` |
| Облачный адаптер (чтение/запись таблиц) | `js/data.js` → `SupabaseAdapter` |
| Вход/выход через Google, сессия | `js/auth.js` → `Auth.signInWithGoogle()`, `Auth.init()` |
| Кнопка «Войти через Google» | `js/screens/settings.js` (появится сама, когда облако настроено) |
| Таблицы и правила доступа (RLS) | `supabase/schema.sql` |

### Логика входа (как это будет работать)
```
Открытие страницы
  └─ Auth.init()
       ├─ облако не настроено → локальный режим (как сейчас)
       └─ облако настроено
            ├─ есть сессия (вы уже входили) → SupabaseAdapter, данные из облака
            └─ нет сессии → локальный режим + кнопка «Войти через Google» в настройках
Нажали «Войти через Google»
  └─ supabase.auth.signInWithOAuth({ provider: 'google' })
       → страница Google → возврат на ваш адрес → supabase-js сохраняет сессию
       → onAuthStateChange → перезагрузка → облачный режим
```
Код `SupabaseAdapter` и `Auth` написан по документации supabase-js v2, но **проверить его можно только
после создания проекта** — рассчитывайте на небольшую отладку на этом шаге.

## 5. Версия 2.0 (с Supabase) — что имеет смысл добавить

1. **Синхронизация компьютер ↔ телефон** — главное, ради чего стоит облако.
2. **PWA**: «установить» приложение на телефон как иконку, работа без сети с досинхронизацией.
3. **Настоящие напоминания** (push) о главном деле и почасовом чек-листе — требует http(s) и разрешения браузера.
4. **Realtime**: изменение на телефоне сразу видно на компьютере (Supabase Realtime).
5. **Недельный обзор** по воскресеньям: мягкие итоги и перенос хвостов одним нажатием.
6. **Повторяющиеся задачи** (каждый понедельник, раз в месяц) — отдельная таблица `task_rules`.
7. **Архив и поиск** по сделанному: «когда я последний раз…».

## 6. Что делать после локальной версии — по шагам

1. **1–2 недели просто пользоваться** локальной версией. Записывать, что раздражает и чего не хватает.
   Это важнее любой технологии.
2. Поправить тексты в `content.js` под свой язык и настроение.
3. Завести репозиторий на GitHub, положить туда папку (удобно откатывать неудачные правки).
4. Попробовать запуск через `python -m http.server` — привыкнуть к http-адресу.
5. Опубликовать на GitHub Pages (пока без облака) — проверить вид на телефоне.
6. Создать проект Supabase, выполнить `schema.sql`, настроить Google-вход (раздел 4).
7. Включить облачный режим, перенести данные из резервной копии.
8. Только после этого — PWA и напоминания.

## 7. Если что-то не работает

- **Пустая белая страница** → откройте консоль (F12 → Console) и посмотрите красную ошибку.
  Чаще всего: файл из `js/` лежит не в той папке или переименован.
- **Данные пропали** → вы открыли другой браузер или другой адрес (file:// и http:// — разные хранилища),
  либо очистили данные браузера. Поможет резервная копия.
- **Нет звука в конце фокуса** → браузер разрешает звук только после взаимодействия со страницей;
  проверьте переключатель в настройках.
- **Таймер «замирает» в фоне** → браузеры замедляют неактивные вкладки, но время считается по часам,
  так что при возвращении таймер покажет верный остаток.
